# خدمة ملاحظات شاشة الجامع

خدمة مستقلة يملكها صاحب مشروع شاشة الجامع. المعاينة تعمل محليًا؛ لا يحدث اتصال أو حفظ تقرير إلا بعد زر الإرسال وتأكيد المشغّل. لا حساب للمُرسل، ولا تحليلات أو إعادة توجيه إلى UrTV أو جهة أخرى. عنوان الخدمة المنشورة هو `https://mosque-tv-reports-adel2184.netlify.app`.

نُشرت الخدمة وفُحصت في 17 نوفمبر 2026: قُبل تقرير اصطناعي ثابت بـ 201، وأعادت محاولته المطابقة 200 دون نسخة ثانية، وتأكد حفظه الخاص بأداة المالك. أعاد فحص الصحة العام 200، ولم يكشف GET التقارير محتوى. ظهر 429 في اختبار موقوت للطلبات غير الصالحة؛ تشرح [Netlify أن تفعيل الحجب قد يتأخر حتى 10 ثوانٍ بعد تجاوز الحد](https://docs.netlify.com/manage/security/secure-access-to-sites/rate-limiting/#enforcement-timing). لا يعني ذلك ضمان حجب فوري للطلب السادس، ولا يُستخدم هذا الفحص دليلًا على إرسال تقرير مستخدم من التلفاز.

## الاستخدام

صفحة `public/index.html` تدعم العربية والإنجليزية. اكتب الملاحظة، ثم أنشئ المعاينة وافحص JSON المعروض حرفيًا. وافق على المحتوى ثم اختر الإرسال وأكد. تغيير الحقول يلغي المعاينة. يعمل التنقيح دون إنترنت، أما الإرسال فيحتاج اتصالًا. الإخفاق أو إغلاق الصفحة لا ينشئ طابور إرسال.

يمكن تضمين الملفات العامة نفسها داخل APK. عند وجود `window.MosqueReportNative.startSend` تستدعي الصفحة هذه الدالة بنص JSON المعروض حرفيًا، ولا تستخدم fetch. يؤكد الغلاف الأصلي العملية ويرسل HTTPS، ثم يعيد حدث `mosque-report-result` بتفصيل `{ok,id?,error?}`. يطبق حدث `mosque-report-language` بقيمة detail إما ar أو en لغة الغلاف. لا تظهر رسالة نجاح إلا بعد `ok:true` ومعرف nonce المطابق. على الغلاف إلغاء العملية عند الإغلاق أو بدء الصلاة ومنع النتائج القديمة؛ تأكيدات نظام Android مستقلة.

أداة الوكيل أو الكمبيوتر تحتاج Node 24 أو أحدث فقط، بلا ADB أو حزم إضافية:

```text
node optimize/share.cjs --preview --problem --owner "تعذر فتح الإعدادات" "ملاحظة إضافية" --app-version 2.5.1
node optimize/share.cjs --preview --setup --owner "اكتمل الإعداد" --out reviewed-report.json
node optimize/share.cjs --send "PATH_PRINTED_BY_PREVIEW" --confirm
```

الأمر الأول يحفظ ملفًا منقحًا في مجلد النظام المؤقت ويطبع محتواه ومساره؛ لا يرسل شيئًا. `--out` يحدد مكانًا تختاره ولا يستبدل ملفًا موجودًا. راجع الملف قبل أمر الإرسال؛ يلزم `--confirm` صراحةً، ويُرسل نفس محتواه دون إضافة بيانات جهاز. الإصدار الافتراضي 2.5.1؛ حدد الإصدار الفعلي عند الإبلاغ عن نسخة أخرى. غلاف POSIX هو `optimize/share.sh` بالوسائط نفسها.

## المخطط والخصوصية

الطلب POST إلى `/api/reports` من نوع JSON وبحد 12KiB. الحقول الوحيدة:

```json
{
  "schemaVersion": 1,
  "category": "problem",
  "message": "Operator-reviewed note",
  "notes": "",
  "appVersion": "2.5.1",
  "androidApi": 30,
  "manufacturer": "TCL",
  "setup": { "disabledCount": 0, "restoredCount": 0 },
  "consent": true,
  "nonce": "77ffb9e7-5e87-4138-91ec-d6d60f2970fd"
}
```

`category` إما problem أو setup، وكل نص حر بحد 2000 حرف. الحقول androidApi وmanufacturer وsetup اختيارية؛ API من 24 إلى 100، والمصنّع واحد من TCL/Sony/Samsung/Other، والعدادات أعداد صحيحة 0..1000. لا تُجمع تلقائيًا. nonce عشوائي UUIDv4 لكل تقرير. الحقول المجهولة مرفوضة. إعادة نفس nonce بالمحتوى نفسه تعيد تأكيد التقرير الموجود؛ المحتوى المختلف لا يستبدله.

يفحص التنقيح أنماط IPv4/IPv6 وMAC والبريد والروابط والهاتف والحقول المسمّاة token/password/SSID/serial وغيرها، ويحوّل الأرقام العربية قبل الفحص. يعيد الخادم الفحص ويرفض أي نص يحتاج تنقيحًا جديدًا. هذا فحص تقريبي قد يحذف نصًا سليمًا أو يفوّت معلومات؛ لا يعد بكشف الأسماء أو إخفاء الهوية. لا تكتب أسماء أو مواقع أو شبكات أو أرقامًا تسلسلية في الملاحظات. لا تُرفق إعدادات الجامع أو الإحداثيات أو الصور أو قائمة التطبيقات.

قد تعالج Netlify عنوان IP وبيانات الاتصال لتقديم الخدمة وتطبيق حد الطلبات؛ لا يحفظ كود الخدمة IP أو الرؤوس أو ملفات تعريف الارتباط أو بيانات الموقع ضمن التقرير، ولا يسجل نصه في console. تبقى التقارير في التخزين إلى أن يحذفها مالك الخدمة؛ لا توجد مدة حذف آلي أو واجهة قراءة أو قائمة عامة.

## التشغيل والنشر

من مجلد `services/reports` ثبّت الاعتماد المثبت `@netlify/blobs11.1.9` ثم انشر عبر مشروع Netlify الخاص بالمالك. مجلد النشر `public` والدوال `netlify/functions`، وتبقى مصادر الدوال خارج الملفات العامة. مجلد `.netlify` وnode_modules متجاهلان محليًا. لا يلزم رمز API في المتصفح أو APK أو CLI.

تستخدم الدالة متجر `reports-production` الدائم فقط عندما يقرر سياق Netlify أن النشر production وpublished=true. أي سياق آخر يستخدم `getDeployStore` باسم `reports-testing` المعزول؛ لا تختبر الكتابة في مخزن الإنتاج. تقرأ الدالة تقاريرها داخليًا فقط للتحقق من تكرار nonce، ولا تعيد محتواها للعامة. يقرأ المالك التقارير ويحذفها من **Data & Storage → Blobs** في لوحة Netlify. لا تستخدم رابط Blob عامًا.

تعيد `/api/health` عبر GET فحصًا للدالة دون أي كتابة أو ادعاء فحص تخزين. حد المنصة المعرّف هو 5 طلبات في 60 ثانية لكل IP؛ الاختبارات المحلية لا تثبت تطبيقه في منصة مستضافة. الطلبات المتقاطعة من المتصفحات مرفوضة، ولا توجد ترويسات CORS أو اعتماد على cookies. عدم وجود Origin مسموح لعميل APK/CLI، مع بقية القيود نفسها. بيانات استقبال الطلب محدودة بالبايتات مع مهلة 5 ثوانٍ. العميل لا يتبع تحويلات HTTP، ولا يعرض نجاحًا عند استجابة غير مؤكدة.

اختبارات محلية فقط، بلا إرسال إلى الخدمة:

```text
node services/reports/test/reports.test.mjs
```

تفحص المعالج الحقيقي بطلبات HTTP معيارية ومتجر مزيف، التنقيح والمخطط والحدود والمهلة وعدم كشف المحتوى، المعاينة/التأكيد في CLI والمتصفح، وفرع الجسر الأصلي. لا ترسل هذه الاختبارات شيئًا إلى الإنترنت. فحص التسليم الحي المنفصل أعلاه استخدم تقريرًا اصطناعيًا فقط وتحقق من مخزن الإنتاج الخاص وسجلات قبول قاعدة الحد، ولا يثبت وحده عمل واجهة التلفاز.

المراجع: [Netlify Functions](https://docs.netlify.com/build/functions/overview/)، [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/). كود الخدمة وأداة المشاركة أصليان؛ لم تُنسخ نصوص UrTV أو وجهات تقاريره.
